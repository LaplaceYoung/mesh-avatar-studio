# Mesh Avatar Studio

[简体中文](README.zh.md) · [日本語](README.ja.md)

Mesh Avatar Studio is a local-first workbench for turning a 2D character illustration into an editable, trackable mesh avatar. It combines rig editing, Live preview, camera tracking, microphone lip sync, OBS output, archive import/export, local image intake, regional evidence, layer production, pose review, and an ACP-based creative assistant in one workspace.

This repository is an independent product fork maintained by [LaplaceYoung](https://github.com/LaplaceYoung). It keeps the original project’s compatible mesh-avatar runtime and gives credit to [shinshin86/mesh-avatar-studio](https://github.com/shinshin86/mesh-avatar-studio) for the foundational runtime, editor concepts, file format, and sample workflow. It is not an official upstream release.

## Product Direction

- **Studio-first editor**: Ant Design 6 and Ant Design X shell with light/dark themes, resizable split panes, inspectors, preview controls, and a floating, draggable Agent window.
- **Local ACP agents**: connect installed Claude Code, Codex, or Pi CLIs without showing a TUI in the product. The browser receives ACP events, tool activity, file diffs, and permission requests; credentials remain in the local CLI environment.
- **Image intake**: validate PNG signatures, CRC, dimensions, pixel limits, alpha coverage, framing, and background risks before production starts. Optional connected-light-background removal is local and keeps `original.png`.
- **Traceable production**: source, regional evidence, draft rig, final rig, built layers, motion review, and human visual signoff are separate states. File existence never equals visual approval.
- **Evidence-driven review**: source hashes, region manifest versions, rig fingerprints, review fingerprints, eye/mouth detail sheets, contact sheets, frame navigation, rest-pose comparison, and continuous blink diagnostics.
- **Mandarin lip sync**: Hanzi, toneless pinyin, pasted tone marks, `ü`, `ui/ue`, omitted-umlaut `j/q/x/y` forms, and explicit unsupported-input feedback.

## Requirements

- Node.js 22.17+
- Git
- Python 3.10+ and `uv` for regional evidence and layer rebuilding
- An installed and separately authenticated Claude Code, Codex, or Pi CLI for ACP Agent work

## Run Locally

```sh
git clone --branch feat/studio-redesign https://github.com/LaplaceYoung/mesh-avatar-studio.git
cd mesh-avatar-studio
npm install
npm run doctor
npm run dev
```

Open `http://127.0.0.1:5173/`. Keep the development server on loopback when Agent features are enabled; do not expose it with `--host 0.0.0.0`.

## Optional Mosi Image Generation

Create `.env.local` locally. Never commit a key or put it in source, prompts, browser storage, logs, or documentation:

```dotenv
MOSS_API_KEY=replace-with-your-local-key
```

The key is used only by the local server proxy. The browser receives a validated PNG, not the provider key or an access-bearing provider URL. Generated bytes are stored under ignored `projects/.uploads/`.

Use a front-facing or near-front-facing head-and-shoulders brief with clear eyes, a readable mouth, separated hair locks, simple accessories, generous margins, and a flat background. Background removal is heuristic and opt-in. Inspect white hair, pale clothes, ribbons, edges, and gaps before production.

## Production Workflow

1. Open the Studio project workbench and upload or generate a source PNG.
2. Review the production preflight and choose whether to keep the original or use local background processing.
3. Explicitly authorize the selected local ACP Agent to inspect the source.
4. Let the Agent create or resume the project. The pipeline protects source hashes and never overwrites an existing project with `--force`.
5. Inspect regional `overview`, `detail`, and `grid` evidence. Eye and mouth regions require fine grids.
6. Validate the draft and final rig, build layers, and inspect eyes, mouth, hair, accessories, and body boundaries.
7. Render and inspect rest, blinking, mouth-open, turns, gaze, tilt, expressions, body motion, hair sway, eye/mouth sheets, and contact sheet.
8. Report concrete defects back to the Agent. Re-render after changes; old evidence and old feedback are rejected by revision fingerprints.
9. Approve visual signoff only after personally reviewing the current evidence. Then open the avatar in the editor or Live page.

The output is a data-driven mesh avatar and Live2D-style runtime asset. It is not a Live2D Cubism project file.

## ACP Agent Behavior

The Agent window is a floating ACP surface, not a terminal emulator. It can be minimized, expanded, dragged, resized on desktop, and closed with `Esc`. It preserves provider identity, permissions, tool calls, file diffs, production progress, reconnect state, and pending approvals. Production turns are bounded, stale evidence is rejected, and same-project production prompts are serialized inside the local bridge.

ACP initialization and a successful tool round-trip do not prove vision quality or avatar completion. Pi availability may also depend on the configured provider account and balance. Treat the production status, evidence images, and human signoff as authoritative for the actual project.

## Diagnostic Commands

These commands produce local evidence and do not run the E2E suite:

```sh
npm run validate-rig -- projects/<name>/rig.json
npm run render-poses -- projects/<name>
npm run render-poses -- projects/<name> --blink-sweep
npm run render-poses -- projects/<name> --blink-sequence
npm run render-poses -- projects/<name> --hide-eye-creases
```

Diagnostic outputs are not official visual approval evidence. Inspect them against the current source, rig fingerprint, and review revision.

## Privacy and Git Boundaries

Source illustrations, generated images, regional crops, review frames, diagnostic projects, and `.env.local` are ignored by Git. Keep them under `projects/` or `work/`. Do not commit user images, provider credentials, cookies, tokens, or access-bearing URLs. `samples/` and `reference/` are upstream-compatible assets and should remain unchanged during product work.
