# Mesh Avatar Studio

[简体中文](README.zh.md) · [日本語](README.ja.md)

Mesh Avatar Studio is a local-first workbench for turning one 2D character illustration into an editable, trackable avatar. It keeps mesh editing, rigging, Live preview, camera tracking, microphone lip sync, OBS output and `.mavatar` archives, while adding image intake, layer production, pose review and local AI assistance.

This is an independent fork and product direction, not an official AITuber OnAir or upstream release. We are grateful to [shinshin86/mesh-avatar-studio](https://github.com/shinshin86/mesh-avatar-studio) for the original runtime, editor concepts, file format and sample workflows.

## What is new in this fork

- **Studio workbench**: Ant Design 6 and Ant Design X provide the editor shell, light/dark themes, split panes, inspectors and a resizable Agent window.
- **Local Agent window**: Claude Code, Codex and Pi connect through ACP and keep their own login, model, tools and permission policy. The browser does not receive API keys or arbitrary executable access.
- **Illustration intake**: local PNG upload validates signatures, CRC, size and dimensions before saving a private source file.
- **Mosi image generation**: an optional server proxy can generate a Live2D-friendly source with `moss-image-sft-1.0`. Original generated bytes are retained, background removal is opt-in, and every image still needs human inspection before rigging.
- **Traceable production flow**: source, regional evidence, draft rig, built layers and pose review are separate states. File existence is not visual approval.
- **Chinese lip sync**: direct Hanzi input and tone-free Mandarin pronunciation previews are supported in the editor.

## Run locally

Requirements: Node.js 22.17+ and Git. Python 3.10+ with `uv` is needed for regional evidence and layer rebuilding. Local Agent integrations require the corresponding CLI to be installed and authenticated separately.

```sh
git clone --branch feat/studio-redesign https://github.com/LaplaceYoung/mesh-avatar-studio.git
cd mesh-avatar-studio
npm install
npm run doctor
npm run dev
```

Open the printed URL, normally `http://127.0.0.1:5173/`. Keep the server bound to loopback when Agent features are enabled; do not use `--host 0.0.0.0`.

### Optional Mosi image generation

Create a local `.env.local` file. Never commit it or put the key in source, prompts, browser storage, logs or documentation:

```dotenv
MOSS_API_KEY=replace-with-your-local-key
```

The key travels only from the local Vite server to Mosi. The browser receives a validated PNG, not the Mosi URL or the key. Use the Studio **Create** flow to enter a short character brief; generated files are stored under ignored `projects/.uploads/`.

The most reliable briefs are front-facing, head-and-shoulders, one character, clear eyes and mouth, separated hair locks, simple accessories and a flat white background. Do not rely on negative wording alone: testing showed that a request for no accessories can still produce hair ornaments. Inspect the face, hair silhouette, pale clothing and accessory boundaries before creating evidence or layers. Background removal is heuristic and disabled by default.

## Production workflow

1. **Create or import a source** in Studio. Prefer a front or near-front illustration with the complete head, neck and shoulders inside the frame.
2. **Prepare evidence** with `tools/vision-regions.py`. Keep crops and source coordinates private; do not estimate anatomy from a full image alone.
3. **Draft and validate the rig** with `npm run validate-rig`, then build layers with the commands in [the Agent guide](docs/agent-guide.md).
4. **Render and inspect poses** with `npm run render-poses`. Check blinking, Chinese mouth movement, turning, tilting, expressions and hair sway. Fix and rebuild when a crop, seam or accessory moves incorrectly.
5. **Sign off visually** only after inspecting the review images yourself. The production panel separates artifact state from human approval.
6. **Open Live** for camera tracking, microphone lip sync, lighting and OBS. Export `.mavatar` only after saving and rebuilding changed outlines.

See [docs/agent-guide.md](docs/agent-guide.md) and [docs/agent-guide.zh.md](docs/agent-guide.zh.md) for coordinate rules and the correction loop. Architecture decisions are in [docs/studio-redesign.md](docs/studio-redesign.md).

The prompt experiment and visual diagnosis for three local Mosi samples are recorded in [docs/mosi-generation-review.md](docs/mosi-generation-review.md); the samples themselves are not committed.

## Local Agents

The floating Agent window starts an installed provider only after an explicit user action. ACP events show messages, plans, tool calls, permission requests and file diffs; permissions are not silently granted. Native CLI configuration is authoritative. Treat this as a local convenience layer, not a security sandbox, and use it only in a repository you trust.

## Privacy and ignored data

Source illustrations, generated images, regional crops, review frames and `.env.local` are ignored by Git. They stay on the local machine unless a user explicitly sends them elsewhere. Do not commit `projects/`, `work/` or credentials.

## Verification boundaries

Claude and Codex have each completed a synthetic ACP tool round-trip locally.
Pi initialized, but its configured inference account returned insufficient balance
during diagnosis. Startup is not proof of inference or vision readiness.

Intake offers optional local white-background removal and original/source comparison.
Review offers eye/mouth sheets, frame navigation and rest-pose comparison, with
revision-bound feedback and approval. White hair/clothing can be damaged by
background removal; artifact validity is not visual approval.

A new illustration completing automatic tracing, rigging and final visual approval
has not yet been verified as a whole. Outputs are mesh avatars, not Live2D Cubism
projects. Diagnostic flags `--blink-sweep`, `--blink-sequence` and
`--hide-eye-creases` write separate evidence, not approved production results.
